# Working in this repository

## Pull requests and commits

- A pull request description is a technical document, not a chat message.
  Use clear, descriptive headings (H1 for the title of the change, H2 for
  each area, H3 for sub-areas) and state exactly what changed, file by file
  or feature by feature. No narrative, no summaries of the conversation, no
  invented section titles.
- Never put tasks for the repository owner in a pull request ("try this on a
  Mac", "please test X"). Anything that needs the owner's involvement is
  raised in the session, not written into the PR.
- Never include "Generated with Claude Code", "Generated by Claude Code", a
  claude.ai session link, or any similar attribution footer in a pull
  request description, commit message, issue, or comment. A session link is
  the serious one: a session holds whatever was typed into it, including
  anything pasted by accident, and none of that belongs in a public
  repository.
- Not writing one is not enough. Opening a pull request appends a footer of
  its own, after the description. Read the description back straight after
  opening one and remove anything of that kind; editing a description does
  not re-append it. That read is also when to check the description arrived
  whole.
- Commit messages describe the change and end there: no `Claude-Session:`
  trailer and no `Co-Authored-By: Claude` line.
- Follow `.github/PULL_REQUEST_TEMPLATE.md` for the facts it asks for: why
  the change exists, what changed file by file, how it was verified, and what
  a reviewer should look at. Its headings can be replaced by descriptive ones.

## Authorship and personal information

- Commits are authored by the contributor who asked for the work and merged
  it, not by a tool. Set `user.name` and `user.email` to the contributor's
  name and their GitHub `ID+username@users.noreply.github.com` address, which
  identifies the account without publishing a personal one. `.mailmap` maps
  older commits to the same identity.
- No personal information in anything published: no personal email address,
  phone number, home address or account handle, in code, comments, commit
  messages, descriptions, issues or fixtures. Use `@users.noreply.github.com`
  addresses and `example.com` in fixtures. The exception is information the
  product itself is for — a business address in a contact page, say — which
  is content, not a leak.
